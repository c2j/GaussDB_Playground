
# 培训课程建设思路指南

## 概述

本文档总结了 `courses/x-professional` 课程库的建设思路，为后续开发新课程提供参考框架。该课程体系采用理论与实践相结合的在线教学模式，通过交互式实验环境，帮助学习者掌握 openGauss 或其他数据库等专业方向及相关技术的核心知识。**特别针对企业内训场景**，强调从理论基础到生产实践的闭环路径，包括新手训练场、实际案例剖析、规范讲解和考试考评，确保培训成果可落地、可量化。

---

## 一、整体架构设计

### 1.1 课程目录结构

```
courses/x-professional/
├── environments/              # 运行环境配置
│   ├── default/             # 默认环境模板
│   └── customization/       # 自定义环境模板
├── courses/                 # 课程目录
│   ├── course-list.json    # 课程注册表
│   ├── course-name-101/    # 单个课程目录
│   │   ├── course-content.json    # 课程元数据配置
│   │   ├── assets/                 # 资源文件（logo、poster、cover）
│   │   ├── exams/                  # 新增：考试模块（题库、脚本、报告模板）
│   │   │   ├── exam-questions.json # 笔试/实操题库
│   │   │   └── report-template.md  # 学习报告模板
│   │   └── chapter-name/          # 章节目录
│   │       ├── index.json         # 章节配置
│   │       ├── intro.md           # 章节介绍
│   │       ├── step1.md           # 步骤内容
│   │       ├── step2.md
│   │       ├── ...
│   │       └── finish.md          # 章节总结
│   └── ...
└── README.md
```

### 1.2 三级组织结构

**课程（Course）**
- 完整的学习单元，包含多个相关章节
- 通过 `course-content.json` 定义课程基本信息和章节列表

**章节（Chapter）**
- 课程的知识模块，专注于特定主题
- 通过 `index.json` 定义章节的步骤顺序和元数据
- 包含多个步骤，形成学习路径

**步骤（Step）**
- 最小的教学单元，单次交互完成一个学习目标
- 通常包含理论讲解、实践任务、验证反馈

**新增：考试（Exam）**
- 课程结束后的考评单元，支持笔试和动手实践
- 通过 `exams/exam-questions.json` 定义题库和评分规则

## 二、理论教学设计

### 2.1 理论内容组织策略

#### 场景化引入
每个课程从实际应用场景切入，建立学习动机。**针对企业内训**，强调业务痛点（如高并发下的数据库瓶颈）。

**示例**：openGauss-101 课程
```markdown
openGauss是一款开源关系型数据库管理系统,采用木兰宽松许可证v2发行。
openGauss内核深度融合华为在数据库领域多年的经验,结合企业级场景需求，
持续构建竞争力特性。本在线实践课程使用openGauss构建金融场景下的数据库，
模拟金融场景下的业务实现，帮助用户掌握数据库基础操作。在企业内训中，可扩展到解决“数据倾斜导致查询慢”的痛点。
```

#### 概念分层讲解
- **基础概念**：定义、作用、特点（如 Schema 的定义和作用）
- **语法规范**：命令格式、参数说明
- **核心原理**：工作原理、设计思想（如 Git 的三区域模型）
- **最佳实践**：使用建议、注意事项（新增：企业规范CheckList，如等保合规要求）

#### 渐进式知识构建
1. 先介绍单个知识点（如创建表）
2. 逐步增加复杂度（如表约束）
3. 综合应用多个知识点（如视图、索引）
4. 引入高级概念（如用户权限管理）
5. **新增：企业视角**：结合生产指标（如RPO/RTO）讲解

### 2.2 理论与实践的结合方式

**先理论后实践**
```markdown
### Schema

`Schema`又称作模式。每个数据库包含一个或多个`Schema`。
数据库中的每个`Schema`包含表和其他类型的对象。通过管理`Schema`，
允许多个用户使用同一数据库而不相互干扰，可以将数据库对象组织成
易于管理的逻辑组，同时便于将第三方应用添加到相应的`Schema`下而不引起冲突。

## 任务

使用gsql工具登录数据库：
`[[gsql -d postgres -p 5432 -r -h 127.0.0.1]]{{RUN}}`
```

**实践验证理论**
```markdown
在SQL编辑框中输入如下语句，创建客户信息表client：
[[CREATE TABLE client (
    c_id INT PRIMARY KEY,
    c_name VARCHAR(100) NOT NULL,
    ...
);]]{{RUN}}

查询`client`表的插入条目数：
`[[select count(*) from client;]]{{RUN}}`
```

**错误演示强化理解**
```markdown
会产生错误。

说明：由于在表的创建过程中，实验定义了`c_id_card`和`c_phone`为唯一且非空
（`UNIQUE NOT NULL`），所以当表中存在时，插入数据失败。
**企业规范**：在生产中，需添加日志审计以追踪此类错误。
```

## 三、实践教学设计

### 3.1 实践任务设计原则

#### 任务明确性
- 每个步骤有清晰的任务描述（使用 `## 任务` 标记）
- 任务目标单一、可量化
- 提供具体的操作步骤

#### 循序渐进
- 基础操作（登录数据库）
- 核心功能（创建表、插入数据）
- 进阶操作（修改、删除、权限管理）
- 综合应用（视图、索引优化）
- **新增：新手训练场模式**：从沙箱环境起步，支持无限重试和快照回滚

#### 即时反馈
- 每个操作后立即验证结果
- 使用查询命令展示执行效果
- 通过错误信息强化正确方法
- **新增：自动评分**：集成脚本计算正确率、性能指标

### 3.2 交互式命令系统

使用自定义 Markdown 扩展语法实现命令执行：

**可执行命令**
```markdown
`[[命令内容]]{{RUN}}`
```

**仅打印不执行**
```markdown
`[[命令内容]]{{PRINT}}`
```

**示例应用**（新增：新手训练场示例）
```markdown
配置Git用户名：
`[[git config --global user.name]]{{PRINT}} "your name"`

初始化Git仓库：
`[[git init]]{{RUN}}`

查看状态：
`[[git status]]{{RUN}}`

**新手训练**：如果失败，点击[回滚]重试。
```

### 3.3 环境准备与依赖管理

#### 环境配置文件
通过 `index.json` 中的 `backend.image_id` 指定容器镜像：
```json
{
  "backend": {
    "image_id": "opengauss-3.0.0"
  }
}
```

#### 依赖提示
对于需要前置学习的章节，添加依赖提示：
```markdown
<font color=darkred>*注意: 本章节学习内容依赖于前面章节的数据及操作，
请先前往前面章节完成相关的操作再进行本章学习*</font>
```

**新增：新手训练场环境**：支持多租户容器，按需分配GaussDB实例（集成华为云API）。

## 六、场景化教学设计

### 6.1 场景选择原则

#### 真实性
选择真实业务场景，提高学习代入感：
- 金融银行系统（openGauss-101）
- 软件开发协作（git-101）

#### 完整性
场景覆盖主要知识点：
- openGauss-101：涵盖建表、数据操作、视图、索引、用户管理
- git-101：涵盖配置、提交、远程协作、冲突解决

#### 连贯性
章节之间保持场景连贯：
- 前置章节创建的数据，后续章节继续使用
- 操作结果影响后续步骤

**新增：生产实际案例剖析+规范讲解**
- 剖析真实故障（如数据倾斜导致雪崩）
- 规范讲解：提供企业级CheckList（如备份策略优化）
- 示例：在金融场景中剖析“慢SQL定位”，并讲解规范（如索引设计规则）

### 6.2 openGauss-101 场景案例

**场景背景**：C银行金融数据库系统

**数据表设计**：
```sql
-- 客户信息表
CREATE TABLE client (
    c_id INT PRIMARY KEY,
    c_name VARCHAR(100) NOT NULL,
    c_mail CHAR(30) UNIQUE,
    c_id_card CHAR(20) UNIQUE NOT NULL,
    c_phone CHAR(20) UNIQUE NOT NULL,
    c_password CHAR(20) NOT NULL
);

-- 银行卡信息表
CREATE TABLE bank_card (
    b_number CHAR(30) PRIMARY KEY,
    b_type CHAR(20),
    b_c_id INT NOT NULL
);

-- 理财产品表
CREATE TABLE finances_product (...);

-- 资产信息表
CREATE TABLE property (...);
```

**业务操作**：
- 添加新客户信息（INSERT）
- 更新银行卡类型（UPDATE）
- 查询有卡客户信息（VIEW）
- 创建索引优化查询（INDEX）
- 用户权限管理（GRANT/REVOKE）
- **新增：案例剖析**：剖析“高并发更新失败”案例，讲解规范（如事务隔离级别）

### 6.3 理论与实践映射

| 理论知识点 | 实践场景 | 操作命令 |
|-----------|---------|---------|
| Schema 管理 | 金融数据库分层 | CREATE SCHEMA finance |
| 表创建 | 客户信息表设计 | CREATE TABLE client |
| 数据插入 | 录入客户信息 | INSERT INTO client |
| 约束管理 | 唯一身份证校验 | UNIQUE NOT NULL |
| 数据查询 | 查找特定客户 | SELECT WHERE |
| 数据更新 | 修改银行卡类型 | UPDATE SET |
| 数据删除 | 清理无效记录 | DELETE FROM |
| 视图 | 有卡客户视图 | CREATE VIEW v_client |
| 索引 | 优化查询性能 | CREATE INDEX |
| 用户权限 | 员工权限控制 | CREATE USER, GRANT |
| **新增：性能优化** | 慢SQL剖析 | EXPLAIN ANALYZE |

## 七、课程开发流程

### 7.1 需求分析阶段

**确定课程目标**
- 学习者是谁（初学者/进阶者，企业DBA/开发）
- 需要掌握哪些知识点
- 预期达到的能力水平

**选择业务场景**
- 适合目标学习者
- 覆盖主要知识点
- 操作流程合理

### 7.2 知识点拆分阶段

**知识点梳理**
- 列出所有相关知识点
- 按学习难度排序
- 识别依赖关系

**章节划分**
- 将相关知识点组合为章节
- 每个章节聚焦一个主题
- 预估学习时间

**步骤设计**
- 将章节拆分为具体步骤
- 每个步骤一个学习目标
- 确保可独立完成

**新增：考试设计**
- 定义笔试/实操题型
- 设置评分维度（正确性、性能、规范）

### 7.3 内容编写阶段

**编写理论内容**
- 概念定义清晰准确
- 原理讲解通俗易懂
- 提供实际案例说明

**设计实践任务**
- 任务目标明确
- 操作步骤详细
- 验证方法清晰

**配置元数据**
- 编写 JSON 配置文件
- 准备视觉资源
- 测试环境配置

### 7.4 测试与优化阶段

**测试执行**
- 按步骤完整执行一遍
- 验证命令正确性
- 检查环境依赖

**用户体验优化**
- 文案是否清晰
- 步骤是否合理
- 是否有歧义

**跨章节测试**
- 验证依赖关系
- 检查数据一致性
- 测试环境复用
- **新增**：模拟企业内训全流程（从理论到考试）

## 八、最佳实践与注意事项

### 8.1 理论编写最佳实践

**简洁明了**
- 避免冗长理论堆砌
- 使用图表辅助说明（如适用）
- 重点内容加粗或高亮

**循序渐进**
- 从简单到复杂
- 从具体到抽象
- 从已知到未知

**联系实际**
- 理论结合场景
- 提供实际案例
- 说明应用价值
- **新增**：融入企业规范（如合规要求）

- 每个步骤可独立完成
- 不依赖未讲解的知识
- 提供完整的操作指引

- 每个操作后验证结果

**安全考虑**
- 不泄露敏感信息
- 使用示例数据
- 避免危险操作

**版本兼容**
- 标注软件版本
- 说明版本差异
- 提供兼容方案

**新增：企业内训注意**
- 确保考试报告可导出（PDF/Excel）
- 支持分组协作（多人内训）

## 九、课程扩展指南

### 9.1 新课程创建步骤

1. **创建课程目录**
将课程保存在courses目录下，比如：courses/x-professional
```bash
cd courses/x-professional/courses
mkdir new-course-101
cd new-course-101
mkdir assets exams  # 新增exams目录
```

2. **准备资源文件**
- logo.png（课程图标）
- poster.png（课程海报）
- cover.png（课程封面）

3. **创建课程配置**
编写 `course-content.json`（包含exam字段）

4. **创建章节**
```bash
mkdir chapter-name
cd chapter-name
touch index.json intro.md step1.md finish.md
```

5. **编写内容**
按照规范编写 Markdown 文件

6. **注册课程**

## 十一、企业内训扩展指南（新增）

### 11.1 内训路径设计

面向企业内训，采用四阶段闭环：
- **理论基础学习**（20-25%）：认知统一，使用知识图谱和短视频。
- **新手训练场**（35-40%）：沙箱实验，支持L1-L4分层（入门到运维）。
- **生产实际案例剖析+规范讲解**（25-30%）：8-12个行业案例，提供决策过程和CheckList。
- **考试考评**（10-15%）：笔试（选择/分析题）+实操（综合项目），生成个人/班级报告。

## 总结

专业培训课程的建设核心理念是**理论与实践的深度结合**：

1. **场景驱动**：以真实业务场景为载体，增强学习代入感
2. **循序渐进**：知识由浅入深，操作从简到繁
3. **即时反馈**：每个操作立即验证，强化学习效果
4. **结构化配置**：JSON + Markdown 实现内容与结构分离
5. **交互式体验**：自定义命令执行系统提供沉浸式学习
6. **新增：企业闭环**：从理论到考试，确保内训成果可量化、可落地

遵循本指南的设计原则和开发流程，可以高效地创建高质量的培训课程，帮助学习者快速掌握 专业及相关技术的核心知识和实践技能。尤其在企业内训中，这将帮助你构建一个真正“值钱”的系统。
