# HA 架构和概念

## 高可用架构类型

### 主备架构
- **定义**: 一个主节点 + 一个或多个备节点
- **优点**: 配置简单，成本低
- **适用场景**: 中小规模应用

### 多节点集群
- **定义**: 多个协调节点 + 数据节点
- **优点**: 读写分离，水平扩展
- **适用场景**: 大规模分布式应用

### 容灾架构
- **定义**: 主备 + 异地容灾节点
- **优点**: 地理隔离，真正的容灾
- **适用场景**: 关键业务系统

## 复制模式

### 同步复制
- **定义**: 主节点等待备节点确认
- **优点**: 数据零丢失（RPO = 0）
- **缺点**: 主节点性能受影响
- **适用**: 关键数据

### 异步复制
- **定义**: 主节点不等待备节点
- **优点**: 主节点性能好
- **缺点**: 可能有数据丢失
- **适用**: 读多写少

### 半同步复制
- **定义**: 至少一个备节点确认
- **优点**: 平衡性能和数据安全
- **适用**: 通用场景

## 故障检测

### 心跳检测
- 主备之间定期心跳
- 超时未响应判断故障
- 自动触发切换

### 集群管理
- 使用 CM（集群管理器）
- 监控所有节点状态
- 自动故障检测和切换

## 切换 vs Failover

### Switchover（计划切换）
- 计划内的切换
- 手动触发
- 用于维护升级
- 有序关机

### Failover（故障切换）
- 意外故障触发
- 自动执行
- 最小化停机时间

## 负载均衡

### 读写分离
- 读请求分散到备节点
- 写请求发送到主节点
- 提升并发性能

### 连接池
- 管理数据库连接
- 提高连接复用
- 减少连接开销

## Tips

**HA 设计最佳实践**:
- 根据业务需求选择架构
- 配置合适的复制模式
- 实施自动故障检测
- 建立监控告警系统
- 定期测试切换流程

**架构选择**:
- 主备: 中小规模，单数据中心
- 集群: 大规模，读写分离
- 容灾: 关键业务，多地部署

**企业规范**:
- [ ] 定义明确的 RPO/RTO 目标
- [ ] 选择合适的 HA 架构
- [ ] 配置自动故障检测
- [ ] 建立监控告警体系
- [ ] 定期测试切换流程
- [ ] 制定应急响应计划

## 任务

查看当前 HA 配置:

```sql
SHOW synchronous_commit;
SHOW synchronous_standby_names;
```

查看复制状态:

```sql
SELECT * FROM pg_stat_replication;
```

查看节点状态:

```
gs_ctl status
```

## 错误演示

备节点未连接:

```sql
-- 如果备节点未启动或网络中断
-- 同步复制会阻塞主节点
SELECT * FROM pg_stat_replication;
```
