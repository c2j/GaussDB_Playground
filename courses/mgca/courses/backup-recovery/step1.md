# 备份概念和策略

## 备份类型

### 物理备份
- **定义**: 复制整个数据库文件系统
- **工具**: gs_basebackup
- **特点**:
  - 快速（文件系统级别复制）
  - 紧凑（压缩后大小小）
  - 增量备份支持
  - 只能整库恢复

### 逻辑备份
- **定义**: 导出 SQL 语句和数据
- **工具**: gs_dump, gs_dumpall
- **特点**:
  - 灵活（可选择表、数据库、模式）
  - 跨平台（文本格式）
  - 可以只恢复部分数据
  - 较慢（需要重新执行 SQL）

## 备份策略

### 全量备份
- **定义**: 备份整个数据库
- **频率**: 每周或每月
- **优点**: 简单，恢复直接
- **缺点**: 备份时间长，需要更多存储空间

### 增量备份
- **定义**: 只备份自上次备份后变化的数据
- **频率**: 每日
- **优点**: 备份快，节省空间
- **缺点**: 恢复复杂（需要链式恢复）

### 差异备份
- **定义**: 只备份自上次全量备份后变化的数据
- **频率**: 每日
- **优点**: 备份较快
- **缺点**: 恢复复杂

## RPO 和 RTO

### RPO (Recovery Point Objective)
- **定义**: 数据丢失容忍度（时间）
- **示例**: RPO = 1小时表示最多丢失 1 小时的数据
- **影响因素**: 备份频率、WAL 归档速度

### RTO (Recovery Time Objective)
- **定义**: 恢复时间目标
- **示例**: RTO = 30分钟表示 30 分钟内必须恢复
- **影响因素**: 备份大小、恢复方法、硬件性能

## WAL 归档

### 归档模式

**archive 模式**: WAL 日志可以被归档到长期存储

```sql
SHOW archive_mode;
```

### 归档配置

在 `postgresql.conf` 中配置：

```
archive_mode = on
archive_command = 'cp %p /archive/%f'
archive_timeout = 300
```

参数说明:
- `archive_mode`: 是否启用归档
- `archive_command`: 归档命令
- `archive_timeout`: 归档超时（秒）

### 备份和恢复策略示例

**策略 1: 每周全量 + 每日增量**
```
周日: 全量备份
周一至周六: 增量备份
```

**策略 2: 每日全量 + WAL 归档**
```
每天: 全量备份
持续: WAL 归档（每 5 分钟）
```

**策略 3: 每日全量 + PITR**
```
每天: 全量备份
持续: WAL 归档
恢复: 可恢复到任意时间点
```

## 备份验证

### 验证备份完整性

定期恢复备份到测试环境验证:
1. 创建测试数据库
2. 恢复备份
3. 验证数据完整性
4. 记录验证结果

### 监控备份状态

- 检查备份是否成功完成
- 监控备份文件大小和增长
- 验证 WAL 归档是否正常
- 设置备份失败告警

## Tips

**备份最佳实践**:
- 制定完善的备份策略
- 定期验证备份完整性
- 保留多个版本的备份
- 存储备份到异地或云存储
- 使用加密保护备份数据
- 监控备份状态和失败告警

**策略选择**:
- 根据 RPO/RTO 要求选择策略
- 考虑存储成本和恢复速度
- 结合 WAL 归档实现 PITR
- 定期测试恢复流程

**企业规范**:
- [ ] 制定明确的备份策略
- [ ] 定义 RPO 和 RTO 目标
- [ ] 启用 WAL 归档
- [ ] 定期验证备份完整性
- [ ] 保留备份到异地
- [ ] 监控备份状态
- [ ] 设置备份失败告警
- [ ] 定期测试恢复流程

## 任务

查看当前 WAL 归档配置:

```sql
SHOW archive_mode;
SHOW archive_command;
SHOW archive_timeout;
```

查看当前备份文件:

`[[ls -lh /opt/gaussdb/backups/]]{{PRINT}}`

查看 WAL 日志:

`[[ls -lh /opt/gaussdb/data/pg_wal/]]{{PRINT}}`

测试 gs_basebackup 帮助信息:

`[[gs_basebackup --help]]{{PRINT}}`

测试 gs_dump 帮助信息:

`[[gs_dump --help]]{{PRINT}}`

## 错误演示

未启用 WAL 归档:

```sql
SHOW archive_mode;
-- 如果返回 off，说明未启用归档
```

说明: 未启用 WAL 归档只能恢复到上次备份点，无法实现 PITR。
